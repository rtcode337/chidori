# ドキュメントの置き場と書き方

| ファイル | 置くもの |
|---|---|
| `README.md` | 入口。何のためのものか（箇条書き 2〜3 行）・できること・起動・使う・運用・ドキュメント表・ライセンス。1 画面（100 行前後）に収める |
| `docs/overview.md` | 立ち位置（Chiezo との関係・名前の由来・題材の線引き）・トップと設定の画面・利用者が書いたことの置き場 |
| `docs/news-and-topics.md` | `/news`（話題・巡回・要約・記事一覧・市況ニュース）、トピックの網と興味トピック、ntfy と端末への通知の動き |
| `docs/relations.md` | 関連図（画家・芸能人）の育て方・図の操作・見た記録 |
| `docs/datasets.md` | データ収集（技術書・Pi-hole・食事処）と travel-log への書き出しの対応表 |
| `docs/operations.md` | 起動・環境変数・イメージ・単体定義・更新・通知の設定・バックアップ |
| `docs/development.md` | mix をコンテナで回す・テスト・CI・スタイルと JS・アイコン・ローカルビルド |
| `docs/basic-design.md`・`docs/technology-selection.md` | 作り始める前の構想。今の実装とは違う（冒頭にその断りがある）。更新しない |

- README には詳細を書き戻さない。節を足したくなったら、先に docs/ へ置けないかを考える
- README から CLAUDE.md へリンクを張らない
- 起動の手順は「GHCR のイメージを pull して動かす」形で書く。ソースからのビルドは `docs/development.md`
- 画面の説明は「なぜその形か」を残す書き方になっている（実測値・やめた形とその理由）。直すときも理由ごと残す
- `**` は Markdown として描かれる場所だけで使い、1 段落にいくつも置かない
- コードコメントから説明を指すときは `docs/<ファイル>.md「節の名前」` の形で書く（README の節を指さない）
- 例に出すホスト名・アドレスは `example.com` / `192.0.2.x` のような実在しないものにする
