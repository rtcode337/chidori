# antenna

日々確認したいニュースや趣味の情報を、利用者ごとの関心に合わせて収集・要約し、適切なタイミングで知らせる情報アンテナアプリです。技術情報に限らず、暮らし、スポーツ、エンターテインメント、地域情報などを扱います。

Elixir と Phoenix で実装し、現在は情報の価値を伝えるトップ画面を表示します。

## Chiezo との関係

antenna は [Chiezo](https://github.com/rtcode337/chiezo) と利用者のあいだに立つ層です。Chiezo が知識と AI を持つ側で、antenna がそれを人に見せ、人の意図を向こうへ渡します。

- Chiezo に溜まった情報を、読める形にして見せる（関連図・ニュース）
- 利用者の関心を Chiezo に伝える
- 何を集めてほしいかの指示を Chiezo に渡す

**題材ごとの事情は antenna が持ちます。** 「画家を集めてネットワーク図にする」のような文脈を Chiezo に持たせると、あちらが題材を選ぶ知識ベースになってしまいます。Chiezo は題材を選ばないまま置き、判断と見せ方はこちらに寄せる、という線引きです。

## 関連図

`/relations` では、人物の家族・コンビ関係と、画家の影響関係・活躍年代をネットワーク図で表示します。

**画家の図は [Chiezo](https://github.com/rtcode337/chiezo) に溜めます。** 「関連図を収集」を押すと、antenna が Chiezo に**整理する収集**（`mode=refine`）を依頼し、その場で 1 回集めさせます。作られるのは止まった状態なので、最初の 1 回は Chiezo の管理画面で有効にしてから押してください（止まっている収集は Chiezo が断ります）。有効にすれば Chiezo が決まった間隔でも図を育て、antenna はそれを読んで表示します。

**名簿・年代・様式は AI に書かせません。** antenna が条件を言葉で書いて渡し、Chiezo がそれを抽出の指定にして、日本語版 Wikipedia から機械的に引きます（生没年のカテゴリから年代、「〜派の画家」などのカテゴリから様式）。AI が書くのは、そこに書いていないこと —— 影響関係と代表作と説明です。

**名簿は「〜の画家」で終わるカテゴリをまとめて指します**（`tag_suffix`）。書き並べると必ず取りこぼすためです —— 名前の付き方が揃っておらず（「イギリス」と「イングランド」は別のカテゴリで、中身は後者に寄っています）、書く側は思い出しで補うしかありません。**地域も年代も絞りません。** 葛飾北斎とゴッホが同じ図に並びます（ジャポニスムは実際の影響関係です）。

**指定を書けなかったときは収集を作りません。** 指定なしで作ると名簿が空のまま AI に肉付けを頼むことになり、数件だけの図ができて終わります。書けなかった理由は画面に出します。

**誰を見るかは AI に選ばせません。** Chiezo が名簿を見出し順に 50 人ずつの区画へ割り、1 回に何区画かずつ渡します。選ばせていた頃は同じ人を何度も選ぶのを止められず、1 日 10 人では一周に何百日もかかりました。巡回は 2 本で、**ざっと**が 14 日で全体を一周し、**じっくり**が 1 日 1 区画を考える量を上げて見直します。進み具合は Chiezo の管理画面で「何区画のうちいくつ回り終えたか」として読めます。

**「ここが間違っている」は割り込みで頼めます**(Chiezo の `POST /v1/collect/<name>/focus`)。定時の巡回の進み具合には触らないので、待たずに直させられます。

**縦軸は年表になっています。** 丸は年代の順に等間隔で並ぶので、目盛りの間隔は一定ではなく、**画家が多い時代ほど広がります**。

**実行のたびに全部を作り直すのではなく、少しずつ良くしていく形**です。1 回で仕上げようとせず、抜けている画家を足す・説明の粗いものを書き直す・粒度を揃える、といった直し方を頼みます。触れなかったものはそのまま残り、消えるのは AI が消すと明示したときだけです。

**図の構造は Chiezo に持ち込みません。** 向こうにあるのは「1 画家 = 1 文書」の普通のソースで、属性と関係はタグに載せてあります。

| タグ | 意味 |
| --- | --- |
| `画家` | この図に取り込む目印 |
| `様式:ポスト印象派` | ノードに添える様式 |
| `年代:1880-1890` | ノード下の年代帯。並び順もこれで決まる |
| `影響元:クロード・モネ:光と色彩` | その画家から受けた影響。線と、線の上の説明になる |

ノードとエッジという読み方を与えるのは antenna 側です。判断や見せ方を Chiezo に持たせない、という線を崩さないための形にしてあります。

### 見た記録

**丸を押して開いた先で、「見た」印とメモを残せます。** 画家の展覧会へ行った、この絵を実物で見た、といった記録は Chiezo には置けません —— あちらは題材も好みも持たない側なので、利用者ごとの事情は antenna が持ちます。印の付いたノードは図の上で**橙色の枠**になります（巡回で動いたものの緑の破線とは別の見え方にしてあるので、自分が付けた印かどうかが読み分けられます）。

残るのは「見たかどうか・いつ・ひとこと」の3つで、**1 ノードにつき 1 件**です。印もメモも空にして保存すると記録ごと消えます。**これは暫定の形**で、同じ画家を何度も見に行く記録（展覧会ごとに 1 件）が要るようになったら、この表を親にして子を足す形へ広げます。

**図を開くたびに Chiezo へ聞きに行きません。** 8,000 人ぶんを読むので数秒かかるのに、Chiezo の側は数時間に 1 度しか動きません。見出しの下に**最後に取得した時刻**が出るので、取り直すかは読む人が決めます（「最新の情報を取得」）。

図の左上には**名前で探す欄**と、その隣に**見た画家を選ぶ一覧**が出ます。名前を思い出せなくても、印を付けたところへは戻れます（並びは見た日の新しい順。図に出ていないものは並びません）。

**人物の図は、まだその場で AI に聞く形**です。収集に失敗した場合は、直前の図または表示例を維持し、失敗した理由を画面に出します。

AI の応答に出典が付いていない関係、実在しないノードを指す関係、`http`/`https` 以外の出典は取り込みません。連続して押したときは間隔を空けます。

## 最新情報

`/news` では、[Chiezo](https://github.com/rtcode337/chiezo) の「集める」層に収集を依頼し、溜まったものを読みます。集めるのは Chiezo で、antenna は依頼と閲覧だけを持ちます。定期実行の時計も、AI の呼び出しも、集めたものの置き場も、すでに Chiezo にあるためです。

**話題ごとにタブで分かれています**（いまは「ニュース」と「技術」）。**話題は antenna の機能**で、関連図の「人物」「画家」と同じ立ち位置です。集め方も関心も話題ごとに違うので、定義は `Antenna.Topics.defined/0` にあります —— 足すときはそこへ 1 つ書けば、タブも収集も増えます。**収集も溜まったものも話題ごとに別**なので、片方を読み直しても、もう片方の状態は入れ替わりません。

**何を集めるかは、話題の「関心」から作ります。** 話題ごとに本文を丸ごと持たせると、話題を足すたびに同じ形の文をもう一度書くことになるためです。`/settings` で決められるのは「誰に頼むか」だけで、関心と名前は定義の側が持ちます（依頼済みの収集の文面を直すのは Chiezo 側から）。

### 収集は仕事ごとに分かれています

関連図と同じく、Chiezo に置く収集は**巡回**に分かれています。1 つの文で全部を頼むと、どの回も同じ薄さの仕事になるためです。画面（`/news`）の「Chiezo の収集」の枠で、巡回ごとに頼む相手を選んで送れます。

| 巡回 | やること | AI |
|---|---|---|
| 見出し / 集める | 溜める回。配信元があれば RSS / Atom から機械的に、無ければ AI に集めさせる | 配信元があれば使わない（相手も選べません） |
| 漏れ探し | 配信元が拾わなかったものを探して足す（足すだけ） | 使う |
| 情報更新 | 前回から入ったものを読んで、重要度と分野のタグを付け直し、宣伝や的外れなもの・重複を落とす | 使う |
| 要約 | 前回から入ったものを 1 件のまとめにする（画面の先頭に出る） | 使う |
| 割り込み | 時計を持たない 1 本。頼まれたときだけ動く | 使う |

**技術ニュースは配信元を持っています**（Publickey・ITmedia NEWS・InfoQ Japan・CodeZine・Zenn・Qiita・はてなブックマーク）。見出し・要約・URL・配信日は機械が正確に取れるので、AI の枠は「何が重要か」「どうまとめるか」へ回します。ニュースと記事は同じ収集に溜まりますが、`ニュース` / `記事` のタグで分けて取り出せます。

**溜めるところは機械、選り分けるのは AI**という分担です。配信元から機械的に取り込むぶん、宣伝記事も的外れなものも混ざるので、落とすのは情報更新の回の仕事にしてあります（落とす力を持つのはこの回だけ）。**消したものは Chiezo が覚えていて**、同じ見出しが次に流れてきても戻りません。

**重要度は AI が付けた印が先です**（`重要度:高` などのタグ）。語の一致だけで決めると、同じ語を含むだけの 1 件が上に出ます。印が無いものだけ、見出しの語で見ます。

**押す口は「Chiezo の収集」の枠にある 1 つだけ**です（関連図と同じ形）。収集がまだ無ければ**止まった状態で**作り、あれば画面で選んだ設定を送り直します。**走らせはしません** —— 動き出すのは Chiezo の管理画面で有効にしたときだけなので、**この画面から AI が勝手に動くことはありません**。有効にすると Chiezo が巡回ごとの間隔で集め、antenna はそれを読みます。

定時の巡回とは別に頼みたいことがあれば、同じ枠の「いま頼む（割り込み）」から 1 回だけ走らせられます（巡回の進み具合にも次の予定にも触りません）。

見出しの横の「優先」は antenna が付けます。災害、避難、金融政策などの語を含む見出しを先に表示します。記事本文は antenna に保存せず、見出しを押すと Chiezo の中身（要約と出典）が開きます。

Chiezo 側で `CHIEZO_COLLECT_DIR` と `CHIEZO_NOTES_DIR` の両方が設定されている必要があります。

| 変数 | 既定 | 説明 |
| --- | --- | --- |
| `CHIEZO_BASE_URL` | なし | Chiezo のルートURL。未設定ならニュースも関連図も使えない |
| `ANTENNA_NEWS_COLLECTION` | `antenna_news` | 「ニュース」の話題が使う収集の名前。Chiezo のソース名になる（他の話題の収集名は定義が持つ） |
| `ANTENNA_NEWS_BACKEND` | なし | 収集を頼む相手（`claude` など）。**話題の「集める相手」が優先**で、ここはそれを決めていないときの既定。どちらも未設定なら Chiezo の既定にまかせる |
| `ANTENNA_NEWS_MODEL` | なし | その相手のモデル |
| `ANTENNA_NEWS_EFFORT` | なし | その相手の考える量 |
| `DATABASE_URL` | なし | PostgreSQL の接続先。本番では必須 |
| `ANTENNA_PAINTERS_COLLECTION` | `antenna_painters` | 画家の図を溜める Chiezo の収集の名前 |

誰に頼むかは本来 Chiezo 側の判断なので、名指しするのは「この収集だけは別の相手に」と決めたときだけです。依頼した後は Chiezo の管理画面からも変えられ、画面には Chiezo が持っている値を出します。

## 設定と選別

`/settings` では、話題ごとに **集める相手** と **選ぶ相手** を別に決められます。決められるのはここまでで、話題の名前と関心と収集名は定義の側が持ちます（定義と DB が別々に動き出さないようにするためです）。役割が違うので、速さと質の釣り合いも別に決めたいためです。集めるのは web を歩く仕事、選ぶのは溜まったものを読む仕事です。どちらも未指定なら Chiezo の既定にまかせます。相手・モデル・考える量はすべてプルダウンから選び、相手を選び直すと候補も入れ替わります。候補は Chiezo に聞くので、こちらに写しを持ちません。

ニュースの画面の「AI に選ばせる」を押すと、溜まったものから **いま読むべきもの** を選ばせます。何が重要かは利用者の関心で決まるので、選ぶのは antenna の仕事です（Chiezo は判断や好みを持ちません）。

**選ぶたびに AI を呼びません。** 溜まったものが変わっていなければ前の結果をそのまま出します。**選ばれなかったものも消しません** —— 選別は絞り込みであって検閲ではないので、選から漏れたものも下に並びます。

## 起動

`docker compose` で PostgreSQL ごと立てる。開発サーバーは `http://localhost:7000`。

```bash
cp .env.example .env   # SECRET_KEY_BASE と CHIEZO_BASE_URL を書く
docker compose up -d
```

`SECRET_KEY_BASE` は `mix phx.gen.secret` で作る。**64 バイト未満だと起動時に断る**
（通すと起動には成功して全リクエストが 500 になり、原因を追いにくい）。
移行は起動のたびに当たるので、手で流す必要はない。

手元のソースから作り直すときは重ねる。

```bash
docker compose -f docker-compose.yml -f docker-compose.build.yml up -d --build
```

ホストで直接動かすなら、DB だけ立てて繋ぐ。

```bash
docker compose -f docker-compose.dev.yml up -d
mix setup && mix phx.server
```

テストは DB が要る。外部への取得はスタブへ差し替えてあるので、ネットワークには出ない。

```bash
docker compose -f docker-compose.dev.yml up -d
mix test
```

アイコンの原本は `priv/static/images/icon.svg`。変えたら PNG を作り直す。

```bash
docker run --rm -v "$PWD/priv/static:/w" -w /w debian:bookworm-slim sh -c \
  'apt-get update -qq && apt-get install -y -qq --no-install-recommends librsvg2-bin \
   && rsvg-convert -w 180 -h 180 images/icon.svg -o images/icon-180.png \
   && rsvg-convert -w 64 -h 64 images/icon.svg -o images/icon-64.png \
   && rsvg-convert -w 64 -h 64 images/icon.svg -o favicon.ico'
```

本番用イメージは `Dockerfile` でビルドする。イメージの中でスタイルと JavaScript も作る。公開時は `ghcr.io/<owner>/antenna:<commit-sha>` のようにコミット SHA を含むタグを付ける。

基本設計は [docs/basic-design.md](docs/basic-design.md) を参照してください。
採用技術と選定理由は [docs/technology-selection.md](docs/technology-selection.md) を参照してください。
