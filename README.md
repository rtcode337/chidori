# tazuna

日々確認したいニュースや趣味の情報を、利用者ごとの関心に合わせて収集・要約し、適切なタイミングで知らせるアプリです。技術情報に限らず、暮らし、スポーツ、エンターテインメント、地域情報などを扱います。

Elixir と Phoenix で実装し、現在は情報の価値を伝えるトップ画面を表示します。

## Chiezo との関係

tazuna は [Chiezo](https://github.com/rtcode337/chiezo) と利用者のあいだに立つ層です。Chiezo が知識と AI を持つ側で、tazuna がそれを人に見せ、人の意図を向こうへ渡します。

- Chiezo に溜まった情報を、読める形にして見せる（関連図・ニュース）
- 利用者の関心を Chiezo に伝える
- 何を集めてほしいかの指示を Chiezo に渡す（tazuna で読むものも、他のアプリで使うものも）

**名前は手綱から採っています。** 知識と AI を持って走るのは Chiezo の側で、こちらはその様子を見ながら、どちらへ向かわせるかを人が決めるための手元です。

**題材ごとの事情は tazuna が持ちます。** 「画家を集めてネットワーク図にする」のような文脈を Chiezo に持たせると、あちらが題材を選ぶ知識ベースになってしまいます。Chiezo は題材を選ばないまま置き、判断と見せ方はこちらに寄せる、という線引きです。

## 関連図

`/relations` では、画家の影響関係・活躍年代と、人物の家族・コンビ関係をネットワーク図で表示します。**最初に開くのは画家の図**です —— Chiezo に溜めて育てているのはこちらで、人物の図はまだその場で AI に聞く形のためです。

**画家の図は [Chiezo](https://github.com/rtcode337/chiezo) に溜めます。** 「関連図を収集」を押すと、tazuna が Chiezo に**網羅の収集**を依頼し、その場で 1 回集めさせます。作られるのは止まった状態なので、最初の 1 回は Chiezo の管理画面で有効にしてから押してください（止まっている収集は Chiezo が断ります）。有効にすれば Chiezo が決まった間隔でも図を育て、tazuna はそれを読んで表示します。

**名簿・年代・様式は AI に書かせません。** tazuna が条件を言葉で書いて渡し、Chiezo がそれを抽出の指定にして、日本語版 Wikipedia から機械的に引きます（生没年のカテゴリから年代、「〜派の画家」などのカテゴリから様式）。AI が書くのは、そこに書いていないこと —— 影響関係と代表作と説明です。

**丸の大きさは知名度で決めます。** 使うのは日本語版 Wikipedia の月次ページビュー（bot 除外）で、これも Chiezo が収集の 1 件ごとに写してきます（`extra.pageviews_month`）。tazuna は収集を読むだけで図を描けます —— 画家 1 人ずつ引きに行っていた頃は、図を開くたびに数千回の往復が要りました。

**事実と判断は別の鍵に持ちます。** ページビューは機械が写す事実で、誰も書き換えません。日本語版の読まれ方が実態とずれている画家（海外で高名だが日本では読まれない、逆に最近の話題で一時的に読まれている）だけ、AI が倍率（`extra.fame_scale`）を書いて直します。同じ鍵を書き換えさせると元の値が失われ、Wikipedia を取り込み直しても新しいページビューを反映できなくなります。

**名簿は「〜の画家」で終わるカテゴリをまとめて指します**（`tag_suffix`）。書き並べると必ず取りこぼすためです —— 名前の付き方が揃っておらず（「イギリス」と「イングランド」は別のカテゴリで、中身は後者に寄っています）、書く側は思い出しで補うしかありません。**地域も年代も絞りません。** 葛飾北斎とゴッホが同じ図に並びます（ジャポニスムは実際の影響関係です）。

**指定を書けなかったときは収集を作りません。** 指定なしで作ると名簿が空のまま AI に肉付けを頼むことになり、数件だけの図ができて終わります。書けなかった理由は画面に出します。

**誰を見るかは AI に選ばせません。** Chiezo が名簿を区画へ割り、1 回に何区画かずつ渡します。選ばせていた頃は同じ人を何度も選ぶのを止められず、1 日 10 人では一周に何百日もかかりました。区画の切り方と巡回の並びは「画家の図の育て方」にあります。進み具合は画面でも Chiezo の管理画面でも「何区画のうちいくつ回り終えたか」として読めます。

**「ここが間違っている」は割り込みで頼めます**(Chiezo の `POST /v1/collect/<name>/focus`)。定時の巡回の進み具合には触らないので、待たずに直させられます。

**縦軸は年表になっています。** 丸は年代の順に等間隔で並ぶので、目盛りの間隔は一定ではなく、**画家が多い時代ほど広がります**。

### 図の操作

**関連図も区画の地図も同じ仕組みで動かします**（`assets/js/pan_zoom.js`）。引きずって移動、Ctrl+ホイールで拡大縮小、指 2 本でつまむ、＋ − 全体 全画面。図ごとに操作が違うと、画面を移るたびに覚え直すことになります。

- **引きずりはいつでも画面移動**です（丸や区画の上から始めても動きます）。込み合ったところで掴める隙間を探さずに済みます。動かさずに離したときは今までどおり選べます
- **拡大は `viewBox` を動かして行います。** 引き伸ばす（CSS の `transform`）と**寄るほど線が粗くなります** —— `viewBox` を狭めればブラウザが描き直すので、どこまで寄っても線は細いままです
- 図ごとの事情だけを足します（関連図は `assets/js/relation_map.js` —— 年代と地域の札を画面の端に留める、見ている範囲をサーバーへ知らせる、探した人へ寄る）

**実行のたびに全部を作り直すのではなく、少しずつ良くしていく形**です。1 回で仕上げようとせず、抜けている画家を足す・説明の粗いものを書き直す・粒度を揃える、といった直し方を頼みます。触れなかったものはそのまま残り、消えるのは AI が消すと明示したときだけです。

**図の構造は Chiezo に持ち込みません。** 向こうにあるのは「1 画家 = 1 文書」の普通のソースで、属性と関係はタグに載せてあります。

| タグ | 意味 |
| --- | --- |
| `画家` | この図に取り込む目印 |
| `様式:ポスト印象派` | ノードに添える様式 |
| `年代:1880-1890` | ノード下の年代帯。並び順もこれで決まる |
| `影響元:クロード・モネ:光と色彩` | その画家から受けた影響。線になり、線を押すと何を受けたかの説明が出る |

ノードとエッジという読み方を与えるのは tazuna 側です。判断や見せ方を Chiezo に持たせない、という線を崩さないための形にしてあります。

### 見た記録

**丸を押して開いた先で、「見た」印とメモを残せます。** 画家の展覧会へ行った、この絵を実物で見た、といった記録は Chiezo には置けません —— あちらは題材も好みも持たない側なので、利用者ごとの事情は tazuna が持ちます。印の付いたノードは図の上で**橙色の枠**になります（巡回で動いたものの緑の破線とは別の見え方にしてあるので、自分が付けた印かどうかが読み分けられます）。

残るのは「見たかどうか・いつ・ひとこと」の3つで、**1 ノードにつき 1 件**です。印もメモも空にして保存すると記録ごと消えます。**これは暫定の形**で、同じ画家を何度も見に行く記録（展覧会ごとに 1 件）が要るようになったら、この表を親にして子を足す形へ広げます。

**図を開くたびに Chiezo へ聞きに行きません。** 8,000 人ぶんを読むので数秒かかるのに、Chiezo の側は数時間に 1 度しか動きません。見出しの下に**最後に取得した時刻**が出るので、取り直すかは読む人が決めます（「最新の情報を取得」）。

図の左上には**名前で探す欄**と、その隣に**見た画家を選ぶ一覧**が出ます。名前を思い出せなくても、印を付けたところへは戻れます（並びは見た日の新しい順。図に出ていないものは並びません）。

**AI がまだ目を通していない画家も図に出します。** 機械で名簿に入っただけの人は**薄い札**になり、図の下の「レビュー済みだけ」「未レビューだけ」で片方だけに絞れます（Chiezo の読み口は既定で未レビューを外すので、`include_removed` で受け取り、消えたものだけを tazuna 側で落とします）。

**図の器は図と同じ縦横比にします。** 画家の図は縦に長いので、画面の高さで切ると拡大しないと下が見えず、全体を入れようと縮めると札が小さすぎて描けません。拡大していない状態で全体が入り、はみ出すぶんはページのスクロールで見ます。

**線の上には文字を置きません。** どの線の説明か読めず、札に重なるためです。線を押すと、AI が書いた「何を受けたか」、受けた側の説明で相手に触れている文、2 人の年代・地域・様式の比較、ほかの影響元が出ます。

**関連の相手は、実在する見出しに限ります**（収集の `verify_tags`。Chiezo が焼く前に落とします）。**代表作は照らしません** —— 作品が単独の記事を持つことは少なく、照らしていた頃は AI が目を通した画家の 9 割で代表作が落ちていました。

**画家を押すと、その人の記事の先頭画像（たいてい自画像か肖像写真）を説明の横に小さく出します。** 引き方は代表作と同じで、無ければ何も出しません。

**代表作は、説明も絵も Chiezo から引きます。** どちらも jawiki に入っています（取り込みが `page_props` ダンプから代表画像を拾って `extra.image` に入れます）。長期記憶を取り込み直す前は画像が入っていないので、**そのあいだだけ**日本語版 Wikipedia に聞きます（入れば通らなくなります）。**結果は 1 日覚えます**。絵が見つからない作品（記事の無いもの、近年のもの）は、**画家名と題名で引く Google 画像検索へのリンク**にします。絵は原寸ではなく縮小したものを指します。

### 画家の図の育て方

収集は **3 つの巡回**に分かれていて、**順番に意味があります**（後のものは前のものが一周するまで走りません）。

| 巡回 | やること | いつ |
|---|---|---|
| 名簿 | Wikipedia のカテゴリから機械的に名前を集める（AI は使わない） | **一度きり**（取り込み直したら押す） |
| ざっと | **年代と地域**を最優先で埋める。ついでに説明・代表作・様式も。明らかに画家でない人は消す | 1 時間ごと・**一周したら止まる**（2〜3 日） |
| 調査 | 区画ごとに、漏れを足す・内容を磨く・要らないものを消す | ざっとが一周してから。6 時間ごと・**一周 20 日** |

**区画は「地域 × 生年」で切ります。** 辞書順で切っていた頃は「Kage〜おおやちき」のような塊になり、同じ区画に入った 2 人に何の関係もありませんでした。**1 年より細かくは割りません** —— 分けると「この範囲の全員」が並ばなくなり、漏れを問えなくなるためです（人の少ない地域は年の幅が自然に広がります）。

**年代と地域が空だと区画が決まらない**ので、その人は「年代不明」の置き場に入ります。そこを埋めるのがざっとの最優先の仕事で、埋まれば本来の区画へ移ります。

**区画の一覧は図の下（Chiezo の収集の枠）にあります。** まだ見ていないものが先に並ぶので、そのまま「次に回ってくる順」です。**「先に調べる」を押すと、その区画を先に見てもらえます**（印が付くので、巡回が同じところをもう一度見ることはありません）。

**未レビューが残る区画は、多い順に別の一覧で並びます。** 「先にざっと見る」を押すと、その区画を**ざっとの回として**先に見てもらえます（AI が目を通すと未レビューの印が外れます）。未レビューの画家を開いたときも、その人の区画を同じように頼めます。区画の所属は、Chiezo と同じ規則で tazuna 側で割り出しています（`Tazuna.Relations.Partitions`）。

**割り込みも調査の回に頼みます**（専用の巡回は置いていません）。画家を名指しした割り込みは区画に印を付けず、区画を名指しした割り込みは印を付けます。

**人物の図は、まだその場で AI に聞く形**です。収集に失敗した場合は、直前の図または表示例を維持し、失敗した理由を画面に出します。

AI の応答に出典が付いていない関係、実在しないノードを指す関係、`http`/`https` 以外の出典は取り込みません。連続して押したときは間隔を空けます。

## 最新情報

`/news` では、[Chiezo](https://github.com/rtcode337/chiezo) の「集める」層に収集を依頼し、溜まったものを読みます。集めるのは Chiezo で、tazuna は依頼と閲覧だけを持ちます。定期実行の時計も、AI の呼び出しも、集めたものの置き場も、すでに Chiezo にあるためです。

**話題ごとにタブで分かれています**（いまは「技術ニュース」「映画」「技術イベント」「ニュース」。**先頭のものが最初に開きます**）。**話題は tazuna の機能**で、関連図の「画家」「人物」と同じ立ち位置です。集め方も関心も話題ごとに違うので、定義は `Tazuna.Topics.defined/0` にあります —— 足すときはそこへ 1 つ書けば、タブも収集も増えます。**収集も溜まったものも話題ごとに別**なので、片方を読み直しても、もう片方の状態は入れ替わりません。

**何を集めるかは、話題の「関心」から作ります。** 話題ごとに本文を丸ごと持たせると、話題を足すたびに同じ形の文をもう一度書くことになるためです。関心と名前は定義の側が持ちます（依頼済みの収集の文面を直すのは Chiezo 側から）。

**古くなり方も話題で違います。** ニュースや記事は日が経てば要らなくなるので期限で落としますが、**技術イベントは「終わったかどうか」だけが古さ**です —— 半年先のイベントを 30 日の期限で落とすと、いちばん要るときに消えます。そういう話題は期限を持たず（`ages_out: false`）、終わったものを整理の回に落とさせます。イベントでは 1 件ごとに**開催日・場所・申込先**を書かせます（この 3 つが無いと、読む人は行けるかどうかを決められません）。

### 流れを追う収集です

Chiezo の収集には**種類**があります。最新情報は**流れ** —— 時とともに増えるものを追っていて、直近だけが対象で、**古いものは順に要らなくなります**（既定で 30 日ぶんを持ち、それより古いものは焼き直しのときに落ちます）。関連図は**網羅**で、ある括りの全部が対象です。増減はしても古いものが要らなくなることはないので、期限では落としません。

### 収集は仕事ごとに分かれています

関連図と同じく、Chiezo に置く収集は**巡回**に分かれています。1 つの文で全部を頼むと、どの回も同じ薄さの仕事になるためです。画面（`/news`）の「Chiezo の収集」の枠で、巡回ごとに頼む相手とモデルを選んで送れます（モデルの候補は相手ごとに違うので、相手を選び直すとそちらのものに入れ替わります）。**考える量の欄はありません** —— Chiezo 側でモデルの名前に畳んであります（`sonnet-high` のような形）。

**ワーカーも相手の選択肢に並びます**（「ワーカー」の見出しの下）。1 つの相手に固定で頼むのではなく、**枠に余裕のある相手へ振り替えながら回す**並びです。選ぶとモデルの欄は消えます —— 渡す先がそのときの枠で決まるので、モデルを 1 つ選んでもどの相手に対する指定なのかが決まりません。

| 巡回 | やること | AI |
|---|---|---|
| 見出し / 集める | 溜める回。配信元があれば RSS / Atom から機械的に、無ければ AI に集めさせる | 配信元があれば使わない（相手も選べません） |
| 整理 | 前回から入ったものを読んで重要度と分野のタグを付け直し、宣伝や的外れなもの・重複を落とし、**そのうえで**配信元が拾わなかったものを外から探して足す（ニュースだけでなく、話題の記事や論文も） | 使う |
| 要約 | 前回から入ったものを 1 件のレポートにする（要旨・要点・章・表・出典に分かれた読み物）。**時計を持たず、tazuna が起こしたときだけ動く** | 使う |

**整理は定時でも回します**（4 時間ごと）。まとめの直前にもう 1 回起こしますが、それだけにすると、落とす仕事も外を当たる仕事もまとめの回数ぶんしか走りません —— ニュースは新しさが落ちると意味が薄いので、間を空けすぎないためです。

**論文は依頼文で名指しして念を押しています。** 外を当たる先の 1 つとして箇条書きに並べていただけの頃は、実測で 269 件のうち論文が 2 件しか入りませんでした —— 4 つ並んだうちの最後の 1 行では埋もれます。配信元は論文を配らないので、**この回が見に行かなければ永遠に入りません**。件数は求めていません（「必ず N 件」と書くと数合わせで薄いものが入り、重要度の印が意味を失うためです）。

**漏れを探す回は分けていません。** 分けていた頃は、重なった時間ぶんを 2 度読ませていました（外を当たる回は直近 4 時間、印を付け直す回は直近 6 時間）。画家の収集が同じ理由で 1 本にまとめてあります（あちらは同じ区画を 3 回渡していました）。**外から見つけたものに、既にあるものを上書きさせない**のだけは依頼文で頼んであります —— 見出しが同じものを薄い要約で返されると、付いている印ごと置き換わるためです。

**技術ニュースと映画は配信元を持っています**（技術: Publickey・ITmedia NEWS・InfoQ Japan・CodeZine・Zenn・Qiita・はてなブックマーク / 映画: 映画ナタリー・CINEMAS＋・BANGER!!!）。見出し・要約・URL・配信日は機械が正確に取れるので、AI の枠は「何が重要か」「どうまとめるか」へ回します。ニュースと記事は同じ収集に溜まりますが、`ニュース` / `記事` のタグで分けて取り出せます。

**巡回の間隔は話題ごとに変えられます**（`every`）。映画は見出しを 6 時間・整理を 12 時間ごとにしてあります —— 1 日で情勢がひっくり返る話題ではないので、短い間隔で回しても同じものを読み直すだけで枠を食います。

**その話題ならではの頼みごとも書けます**（`note`。整理の回の依頼文に足されます）。関心が「何が読む価値があるか」なのに対して、こちらは「1 件ごとに何を書き足すか」です。映画では、**評判（口コミの傾向）と興行成績**を出どころの URL つきで足させ、**口コミの本文は写させません**（転載になるうえ、1 人の感想は作品の評判ではありません）。**結末や仕掛けも書かせません** —— 読む人はまだ観ていません。

**整理はまとめに触りません。** まとめは同じ出来事に触れているので重複に見えますが、落とすと画面と通知からまとめが消えます（実際に消えました）。依頼文で「`まとめ` のタグが付いたものには触らない」と頼んであります。

**消えたものと、まだ整理が読んでいないものは画面に出ません。** Chiezo は消したものを消さずに印（`_chiezo_removed`）を付けて残し、機械で引いたばかりのものにも印（`_chiezo_unreviewed`）を付けます。**落とすのは Chiezo の側**で、どの読み口でも既定で外れます —— tazuna が選り分ける形にすると、印が増えるたびにこちらも直して回ることになり、しかも漏れるのは読者の画面だけなので気づくのが遅くなります。

**まとめは直近の窓から拾いません。** タグで引き直します —— 見出しの回が 60 件足すと、まとめは直近の一覧から押し出され、**まとめが出ない時間帯ができます**。

**溜めるところは機械、選り分けるのは AI**という分担です。配信元から機械的に取り込むぶん、宣伝記事も的外れなものも混ざるので、落とすのは整理の回の仕事にしてあります（落とす力を持つのはこの回だけ）。**消したものは Chiezo が覚えていて**、同じ見出しが次に流れてきても戻りません。

**同じ記事を二度足させません。** 既に入っているかは**見出しではなく URL で**確かめさせます —— 同じ記事が配信元ごとに違う見出しで流れてきますし（「記事名 - サイト名」と「記事名」）、整理の回に差し込まれるのは前回から後に入ったぶんだけです。**見出しの付け替えもできません**（別の見出しで返すと、同じ URL の 1 件として Chiezo に弾かれ、元の見出しのまま残ります）。**まとめは記事の URL を名乗りません** —— 引いた記事の URL を入れると、その記事が既にあるぶんと同じ 1 件とみなされ、まとめ自体が入りません（出典は本文に書きます）。

**記事に絵が付くことがあります。** 配信元がフィードで配っているぶんだけです（ページを取りに行くのは本文を取ることになるのでしません）。実測では、はてなブックマークと Zenn が配っています。

**まとめはレポートとして出ます。** 画面（`/news`）の先頭に出るのは、要旨・要点・章・表・出典に分かれた読み物です。溜まったものをそのまま並べても読めないので、何が起きたかと、なぜ押さえるべきかを先に言います。**章の番号と目次と出典一覧は画面の側で付けます** —— 本文に書かせると、章が増えた回に番号がずれます。

**出典は記事の見出しでリンクになり、章にはその記事の絵が 1 枚だけ付きます。** まとめには `出典: [記事の見出し](URL)` の形で書かせ、tazuna はその見出しで Chiezo から記事を引き直します —— 画面に並んでいる直近のぶんと突き合わせる形にはしていません。まとめは前回から今回までに入った全部から引くので、そこに収まる保証がないためです（実測では、直近 20 件との一致は 13 本中 0 本、50 件でも 7 本）。**見出しは Chiezo の中で 1 件を指す鍵**なので、引き直せば窓の大きさに関係なく当たります。絵は配信元がフィードで配っているぶんだけなので、付かない章もあります。

**一覧は重要度の順に並びます。** 先頭に出るのは要約の巡回が書いたまとめで、その下に 1 件ずつが「優先 / 注目 / 急がない」の順で並びます。同じ重さのものは新しい順のままです。**低いものも消しません** —— 重要度は並びであって、ふるい分けではないためです。

**重要度は AI が付けた印が先です**（`重要度:高` などのタグ）。付けるのは整理の巡回で、読んだうえでの判断です。語の一致だけで決めると、同じ語を含むだけの 1 件が上に出ます。印が無いものだけ、見出しの語で見ます（災害・避難・金融政策など）。

**どれだけ反応されているかは別の軸で持ちます**（`話題度:高` などのタグ。整理の巡回が付けます）。重要度に混ぜると、**話題になっていないが効く 1 件**と**効かないが沸いている 1 件**が同じ印になり、どちらの読み方もできなくなります。**数は持ちません** —— 配信元は反応の数を配らないので、付けるのは読んだ AI の判断です（同じ出来事を何本の媒体が報じているか、人気枠から入っているか）。印の無いものには何も出しません（まだ読まれていないだけの 1 件が「話題になっていない」として並ばないように）。

**押す口は「Chiezo の収集」の枠にある 1 つだけ**です（関連図と同じ形）。収集がまだ無ければ**止まった状態で**作り、あれば画面で選んだ設定を送り直します。**走らせはしません** —— 動き出すのは Chiezo の管理画面で有効にしたときだけなので、**この画面から AI が勝手に動くことはありません**。有効にすると Chiezo が巡回ごとの間隔で集め、tazuna はそれを読みます。

定時の巡回とは別に頼みたいことがあれば、同じ枠の「いま頼む（割り込み）」から 1 回だけ走らせられます（巡回の進み具合にも次の予定にも触りません）。**走るのは整理の回です** —— 専用の巡回は置いていません。頼まれるのはたいてい「これは宣伝だから落として」「この印が違う」で、**落とす力と印を付け直す力を持つのはこの回だけ**だからです。

## トピック

記事から育った**話題の網**を図にします。一覧が 1 件ずつの索引、まとめがその期間の読み物だとすれば、こちらは**どの話題がどうつながっているか**です。**置き場所は `/news` の、まとめのすぐ下**です —— まとめが「この期間に何があったか」を文で言うのに対して、図は同じことを語のつながりで見せるので、別のページに置くと読む人が見に来ません。**出すのは持つ話題だけ**です（いまは技術ニュース。記事が毎日まとまった数で流れてこないと、網になる前に語が古くなります）。

**語を拾うのは機械です。** 記事に付いたタグがそのままトピックになり、件数も一緒に出てくる語も Chiezo が数えます（`extract` の `of: "tags"`）。AI に語を思いつかせていた頃は、**記事に出てこない語が混ざり、同じ話題が回ごとに違う表記で増えました**。

**だから、記事のタグに固有名を書かせます**（製品・サービス・技術・組織の名前。集める回と整理の回のどちらにも頼んであります）。分野だけだと「AI」「セキュリティ」のような広い語ばかりになり、**どの記事も同じ場所に集まって図になりません**。配信元が 1 件ごとに付けている語（Qiita や Zenn のタグ）も Chiezo が材料として渡すので、書き手が付けた綴りをそのまま使えます。

**AI がやるのは精査だけです。** 言い換えを 1 つに畳む・親子を決める・技術の話でない語（媒体名や一般語）を外す・一言で説明する —— どれも数では決まりません。粒度が違うだけの語は畳ませず（畳むと片方が消えます）、**迷ったものは触らせません**（間違って外した語は二度と入りません。1 回見送るほうがずっと安い）。**tazuna は依頼文を渡して、できたものを読むだけ**です。

**溜め先は記事とは別の収集**（`<話題>_topics`。網羅）です。記事と同じ収集に置くと、流れの期限（30 日）でトピックまで消えます —— トピックは、増減はしても古いものが要らなくなるものではありません。

| 巡回 | やること | 間隔 |
|---|---|---|
| 機械収集 | 記事のタグを名簿にし、件数・直近の件数・一緒に出てくる語を数え直す。**AI を呼びません** | 1 時間 |
| 整理 | 手元の語を読んで、言い換えを畳み、親子と分野を決め、話題でない語を外す | 6 時間 |

**整理の回に渡すのは見出しとタグだけ**です（Chiezo の `{names}`）。本文まで見せると、語が増えるほど入り切らなくなり、しかも**切れるのは新しいほう** —— いちばん見てほしい「まだ精査していない語」が落ちます。**始めるのはその未精査のものから**で（`分野:` の付いていないもの）、1 回で終わらなくても次の回が続きから読みます。

**AI は自分でも Chiezo を引けます。** 収集の AI は Chiezo の MCP（`/mcp/knowledge`）に繋がっているので、渡した材料で足りなければ `search` / `doc` / `filter` で手元の知識を引いて確かめられます。**`query` で SQL も引けます** —— 同じ記事に一緒に付いたタグを数えられるので、つながりを思いつきで引かずに済みます。**読むだけ**です —— 短期記憶へ書く道具（remember / update / forget）は、この口には出していません（無人で回る回が書けると、人が覚えさせたものと機械が書いたものが同じ置き場で混ざるためです）。

**図の語彙は tazuna が持ちます**（関連図の画家と同じ形）。読む側と書かせる側が離れると静かにズレるためです。

| タグ | 意味 |
| --- | --- |
| `トピック` | この図に出す目印 |
| `分野:AI` | 色分け |
| `親:AI` | 上位のトピック（点線の矢印になる） |
| `同義:エージェント` | 畳んだ言い換え（図には出さない） |

数のほうは脇書きに入ります（**機械が毎回入れ替えます**）。`docs` / `docs_recent` がその語の付いた件数と直近の窓のぶん、`last_seen` が最後に付いた日、`links` が一緒に出てくる語（`語:回数`）です。

**丸の大きさは直近の件数です。** 件数の合計だと、昔よく出てきた語がいつまでも大きいままになります —— 図で真っ先に読みたいのは「いま何が太いか」です。いちばん動いている語を基準にした割合で描くので、静かな日でも図は潰れません。**0 件になっても消さず、小さく描きます**（静かになったことも図から読めるように。いつまで動いていたかは一覧に出ます）。**線は一緒に出てきた回数**で、太さもその回数です —— AI に関連を書かせていた頃は、一度も一緒に出ていない組が線になっていました。**円環に並べるのは、開くたびに形が変わると「昨日と同じ図か」が読めなくなる**ためです（並びは分野ごと、同じ分野の中は名前の順。同じ材料なら同じ図になります）。

**先の無い線は引きません。** 一緒に出てきた相手が、外された語や図の外のこともあるので、両端が図にあるものだけを線にします（一覧にはそのまま出します —— 黙って消すと、何が起きているのか読めません）。

### まとめを ntfy で知らせます

**通知へ流すのは、レポート冒頭の要旨だけです。** 要旨は通知に流す前提で別に書かせています（**1 行目でその期間を一言、空行、要点を「・」で 3〜4 行**。記号の飾りなし）—— 全部を 1 つの段落に詰めると、通知でも画面でも読めません。通知は畳まれて先頭しか見えないことがあるので、**1 行目だけで意味が通るように**頼んであります—— レポートを潰して送ると、見出しも表も箇条書きも記号のまま並びます。同じ文が画面ではレポートの導入として出ます。**見出しは本文に写しません**（ntfy はタイトルを別に持つので、二度並びます）。出典の URL は、末尾に 3 件まで添えます。

**画面と通知で、出典の出し方が逆です。** 画面では出典の URL を**記事の見出しでリンク**にします（裸の URL のままだと、押す前にどこへ行くのか読めません）。通知では **URL のまま**渡します —— ntfy が自分でリンクにするので、見出しに差し替えると行き先が読めないただの文字になります。

**時刻は tazuna が持ちます。** `/news` の「まとめを知らせる（ntfy）」に「知らせる時刻」を書くと（JST、`07:00,21:00` のようにカンマ区切り。空なら回りません）、その時刻に **整理を 1 回起こす → 要約を起こす → できたまとめを知らせる** まで tazuna が進めます。**Chiezo には「いま回してください」としか言いません** —— あちらは題材も都合も持たない側で、何時に読みたいかは利用者の都合だからです。

**要約は時計を持ちません**（Chiezo 側では `on_demand` の巡回）。間隔で回していた頃は、回るたびに時刻がずれていくうえ、**いつ回ったかが分からないと知らせようがありません**。起こすのがこちらなら、できあがりを待って知らせられます。

**整理を先に起こすのは、整理されていないものでまとめさせないため**です（宣伝も重複もそのまま読み物に入ります）。起こした先は待ってくれない（Chiezo の口は「起こした」まで返す）ので、終わったかどうかは tazuna が読み直して確かめます —— 整理は収集の前回時刻が進んだか、まとめは見出しが変わったかで見ます。

**いまの状態と、前に走った回の記録は分けて出します。** 画面には「いまは動いています（次の定時の回は…）」と「前回の定時の回: …」が別の行で出ます —— 止まった回の理由は現在形で残るので（「Chiezo 側で止まっています」）、記録だと断らないと**ずっと前に止まった回の理由が、いまの状態として読まれます**（実際に読まれました。そのときは収集も要約も動いていました）。

**その場で作らせることもできます**（「いま作って知らせる」）。作り直さずに送るだけの「いまのまとめを知らせる」も残してあります。**押されたときは、知らせ済みでも送ります** —— 押すのは意思表示なので、そこで黙られると「壊れているのか、もう送ったのか」が分かりません（最後に知らせた時刻は画面に出ます）。

**通知を押して開く先は、外から開ける宛先があるときだけ添えます**（`PHX_HOST`）。手元しか指せないとき（既定の `localhost`）は添えません —— 通知を開くのはたいてい別の機械で、電話で押しても `localhost` は自分自身を指すので、開けないリンクが付くだけです（添えなければ、その通知は本文をそのまま扱えます）。

**同じ回は二度走らせません。** 走らせる前に予定の時刻を控えるので、数分かかる段取りの最中にその回がもう一度来ても起こしません。予定を逃したときは 30 分までなら走らせ、それより過ぎたものは追いかけません（夜中に立ち上げた拍子に朝の回が走らないように）。

**通知先は画面から、話題ごとに決めます。** 宛先は運用しながら変えるもの（試しに別のトピックへ流す、しばらく止める）なので、環境変数だと変えるたびに立て直しが要ります。**空にすれば知らせなくなります。** 既定の宛先は持ちません —— 公開の ntfy では、推測できる名前は誰でも読めるためです（推測されない名前にしてください）。

**ntfy の場所は、書かなければ公式の公開サーバー（`https://ntfy.sh`）へ送ります。** 自前で立てているなら `NTFY_BASE_URL` に既定を置くか、話題ごとに画面から上書きできます。場所まで空を「知らせない」の意思表示にしていた頃は、**宛先だけ書いた人のところに何も飛ばず、その理由は画面の隅にしか出ませんでした**（実際にそうなりました）。送るかどうかを決めるのは宛先のほうです。

**届かなかったものは知らせた扱いにしません** —— 記録すると、次からは黙って飛ばされ、そのまとめは永遠に届きません。

記事本文は tazuna に保存せず、見出しを押すと Chiezo の中身（要約と出典）が開きます。

Chiezo 側で `CHIEZO_COLLECT_DIR` と `CHIEZO_NOTES_DIR` の両方が設定されている必要があります。

| 変数 | 既定 | 説明 |
| --- | --- | --- |
| `CHIEZO_BASE_URL` | なし | Chiezo のルートURL。未設定ならニュースも関連図もデータ収集も使えない |
| `TAZUNA_NEWS_COLLECTION` | `tazuna_news` | 「ニュース」の話題が使う収集の名前。Chiezo のソース名になる（他の話題の収集名は定義が持つ） |
| `TAZUNA_NEWS_BACKEND` | なし | 収集を頼む相手（`claude` など）。**これは収集ぜんたいの下敷き**で、巡回ごとの相手は画面の表から選ぶ（巡回に書いてあればそちらが勝つ）。未設定なら Chiezo の既定にまかせる |
| `TAZUNA_NEWS_MODEL` | なし | その相手のモデル |
| `TAZUNA_NEWS_EFFORT` | なし | その相手の考える量 |
| `DATABASE_URL` | なし | PostgreSQL の接続先。本番では必須 |
| `TAZUNA_PAINTERS_COLLECTION` | `tazuna_painters` | 画家の図を溜める Chiezo の収集の名前 |
| `TAZUNA_MEALS_COLLECTION` | `tazuna_meals` | 「食事処」を溜める Chiezo の収集の名前（travel-log が読む先） |
| `TAZUNA_BOOK_POSTS_COLLECTION` | `tazuna_book_posts` | 「技術書を勧めている記事」を溜める Chiezo の収集の名前 |
| `TAZUNA_BOOKS_COLLECTION` | `tazuna_books` | 「本棚（定番の技術書）」を溜める Chiezo の収集の名前 |
| `NTFY_BASE_URL` | `https://ntfy.sh` | ntfy のルートURL の既定。**通知先（トピック）は画面から決める**（空なら知らせない） |

誰に頼むかは本来 Chiezo 側の判断なので、名指しするのは「この収集だけは別の相手に」と決めたときだけです。依頼した後は Chiezo の管理画面からも変えられ、画面には Chiezo が持っている値を出します。

## データ収集

`/datasets` では、**他のアプリで使うデータ**を Chiezo に集めさせる依頼を出します。関連図や最新情報と違い、**この画面は溜まったものを見せません** —— 読むのは使う側のアプリで、こちらが持つのは依頼と進み具合だけです。同じものを 2 つの画面に出すと、どちらが本当の状態なのか読めなくなります。

**集めるものごとにタブで分かれています**（いまは「食事処」「技術書」）。定義は `Tazuna.Datasets.defined/0` にあります —— 足すときはそこへ 1 つ書けば、タブも依頼も増えます。

### 定番の技術書

**「良い本」ではなく「勧められている数」で決めます。** 1 人が絶賛した本と、何十本の記事が挙げてきた本は別物で、後者が「技術者なら読んでいる」に当たります。

**そのために、本ではなく記事を溜めます。** AI にその場で探させて数えさせると、**同じ本が次の回では見つからず、数が増えたり戻ったり**します —— 記事のほうを溜めておけば、同じ材料からは同じ数が出ます。収集は親子の 2 つです。

| 収集 | 何が溜まるか | 誰が |
|---|---|---|
| `tazuna_book_posts` | 技術書を勧めている記事 | 拾う（機械・はてなの検索 RSS）／ 読む（AI が記事を開いて「本:<書名>」のタグを付け、手元に無い記事も探す） |
| `tazuna_books` | 本棚（1 冊 1 文書） | 拾う（機械・タグを数えるだけ）／ 整える（AI が言い換えを畳み、分野を付け、技術書でない語を外す） |

**立ち上げは人気順、定常は新着順**です。定番の根拠は何年も前の記事にあるので、新着だけを追っても永遠に届きません —— 人気順はページを繰れるので、1 周目で過去を拾い、2 周目からは新着だけが足されます（同じ記事は見出しと URL で弾かれます）。

**数は機械が数えます。** その本のタグが付いている記事の数が、そのまま「何本の記事が勧めているか」です。**AI は数に触りません** —— 畳む・分野を付ける・説明する、だけが AI の仕事です（トピックの網とまったく同じ形）。

### 食事処（travel-log 向け）

travel-log の地図に並べる「食べに行く先」を、日本全国ぶん集めます。**網羅の収集**なので、期限で古いものを落とすことはしません（落とすと地図に穴が開きます）。

**名前と座標は AI に書かせません。** 名簿は Chiezo の 3 つの辞典から機械的に引きます —— 座標を書かせると当てにならない値が混ざり、しかも実行のたびに違う値になります。AI に頼むのは、そこに書いていないことだけです（まだ開いているか・食べに行く先か・どう紹介するか）。

**ひとつの辞典では要る項目が揃いません。** 同じ店が複数の辞典に居たときに、どの項目をどこから採るかまで決めてあります。

| 辞典 | 件数 | 勝つ項目 | なぜ |
|---|---|---|---|
| 百科事典（`jawiki`） | 約 900 | 説明・出典 | 読み物になる紹介文があるのはここだけ |
| 地図辞典（`osm_japan`） | 約 10 万 | 座標・住所・サイト | 現地を歩いた人が置いた点で、いちばん確か |
| 店舗辞典（`overture_japan`） | 約 41 万 | （何も勝たない） | 件数はいちばん多いが、値の確かさは上の 2 つに劣る |

**順位を譲ることと、その値を捨てることは別です。** 百科事典は座標で勝ちませんが、地図に載っていない 1 軒の座標はそこにしか無い —— 捨てると、**その 1 軒はどの区画にも入らず、AI から永遠に見えなくなります**（区画は座標で決まるため）。Chiezo は勝った辞典で埋めたあと、空いたところを残りの辞典で埋めます。

**どの辞典も絞りません。** 網羅の収集なので、機械で引けるものを取りこぼすと、そのぶんを巡回が区画ごとに探し直すことになります —— **機械で済む仕事を AI に払わせる**形です。地図辞典にはもう一段の理由があり、あちらは飲食店にどれも同じ点しか付けないので、件数を書くと並びが見出し順になり、名前が先に来るものだけが残ります（数字と英字の名前が入って、仮名の途中で切れる）。

| | |
|---|---|
| 名簿 | 約 60 万件（日本のぶんだけ） |
| 区画 | 1 区画 150 件を目安に切る（件数が増えれば区画も増える） |
| Chiezo の素材 | 1 件あたり約 256 バイト |
| 取り込み時のメモリ | 1.6 GB 前後。**前世代も同時に載るので定常では倍**を見てください |

**一周の長さは、区画の大きさではなく件数で決まります。** AI は 1 件あたり約 1.1 秒（実測）で、Chiezo は区画ごとに 1 回ずつ直列に聞きます —— 52 万件なら、回し続けても 6.6 日が下限です。**区画を大きくしても一周は縮みません**（同じ店を同じだけ読ませるので）。減るのは 1 回ごとの定型文の無駄だけです。

**一周にかかる日数は、こちらでは決め打ちしません。** 巡回に書くのは「これくらいで一周したい」という希望で、実際の速さは**区画の数**と**Chiezo が 1 回に見る区画の上限**で決まります —— 区画が増えれば伸びますし、上限に当たれば書いた日数には届きません。**いま何日かかるかは Chiezo の画面**（収集の面の巡回の表）で読んでください。ざっとは一周したら止まるので、費用は立ち上げの一度きりです。

**1 区画の大きさは、入り口ではなく出口で決めています。** この回は残す店ぜんぶにタグと紹介文を付けさせるので、区画の件数がそのまま AI の返す件数になります。実測では **150 件が切れずに全部返り**、47,685 文字・2 分 50 秒でした（1 件あたり約 318 文字）。切れると実害が出ます —— ざっとは一周したら止まるので、返らなかった店は中身が空のまま残り、**次に見られるのはじっくりが回ってくるずっと先**です。

**同じ店が 2 つに分かれることがあります。** 畳めるのは見出しがそのまま一致したときだけで、実測では、同じ範囲の地図辞典と店舗辞典で名前が一致するのは 3%（60m 以内という条件を足しても 2〜9%）。**畳めなかったぶんは別の 1 件として並びます** —— 気づけるのは区画をまとめて見る AI の回のほうなので、そちらに「1 つにまとめてください」と頼んであります。どちらの値を残すかは 1 件ごとに付いた出典のタグで決めます（座標は `出典:OSM`、説明は `出典:Wikipedia`）。一方、**百科事典の見出しは辞典とよく一致します**（東京都の飲食店 128 件のうち地図辞典に 47 件・店舗辞典に 72 件）。紹介文が要るのはまさにそこなので、この形がいちばん効きます。

**区画は座標で割ります**（店の多いところは細かく、少ないところは粗く）。母集団は集めたもの自身で、対象の矩形には日本全体を書いてあります。

- 母集団を自分自身にするのは、**そのときだけ Chiezo が区画を割り直す**ためです。座標が直れば区画もそれに追随します。
- 矩形を書くのは、**まだ 1 軒も入っていない範囲を対象から落とさない**ためです。点から矩形を作ると点の無いところは矩形の外になり、「ここに足りない店はないか」を永遠に問えません。

| 巡回 | やること | AI |
|---|---|---|
| 名簿 | 3 つの辞典から機械的に引く（一度きり・足すだけ） | 使わない（相手も選べません） |
| ざっと | 区画を一周して、座標を直し・閉店を消し・中身を埋める（一周したら止まる） | Chiezo の AI |
| じっくり | 区画ごとに、**足りない店を足す**（ついでに精査も） | **手で回す**（web の画面から使う AI） |

**どちらも名簿ができてから走ります。** 名簿が無ければ区画には何も並ばず、空の一覧に向かって「この範囲の全部です」と言うことになります。

**じっくりだけ手で回します。** 「この範囲にあって並んでいない店」を探すのは web を何度も引く仕事で、Chiezo から呼べる相手では 1 区画 6〜14 分かかり、上限で切れることもありました（実測）。画面から使う AI（Gemini など）には鍵も API も要らず、調べものはそちらのほうが速い —— **Chiezo が依頼文をファイルに書き出す**ので、渡して、答えのファイルを読み込ませます。**こちらの AI の枠も取り込みの番も使わない**ので、ざっとの一周を待たせていません。

受け渡しは Chiezo の収集の面（`/admin/collect/<収集名>`）の「手で回す」から。束を作る → ファイルを取って渡す → 答えを読み込む、で、そこから先は AI に頼んだ回とまったく同じ道で焼かれます（区画の印も、墓標も、重複の弾き方も）。**割り込み（「この区画を先に調べて」「この店が違う」）はざっとが引き受けます** —— 人が待っている場面なので、その場で聞ける回でないと意味がありません。

**集めるのはイートインできる店だけです。** 持ち帰り専門の弁当・惣菜・菓子の店、百貨店の地下や駅ナカの物販売場は、地図に並べても行き先にならないので外させます（**持ち帰りもやっている店は残します** —— 寿司屋や麺類の店の持ち帰りは、その店の一部です）。

**座標のずれは、消す理由にしません。** 直させるのは座標のほうです —— 「本来の区画へ移す」つもりで消されると、移った先の回はその店を知りませんし、消したものに立つ墓標が名簿からの復帰も止めるので、**そこで消えたまま**になります（実際に 2 件起きました）。依頼文でそう書き切ってあります。

**押す口は「Chiezo の収集」の枠にある 1 つだけ**です（関連図・最新情報と同じ形）。収集がまだ無ければ**止まった状態で**作り、あれば tazuna が持っている抽出の指定・依頼文・区画の割り方・巡回を送り直します。**走らせはしません**。区画の一覧から「先に調べる」を押すと、その区画だけを先に見てもらえます（定時の巡回の進み具合にも次の予定にも触りません）。

**区画は地図にもなります。** 「8,185 区画のうち 2 つ見終わり」と数で言われても、**それがどこなのかは読めません** —— 四角を並べて、見終わったところを緑で出します（薄い緑が片方、濃い緑が 2 本とも見終わったぶん）。**進み具合は巡回をまとめて測ります** —— 1 本だけを見ると、もう片方が回っているのに「まだ」のままになります。

- **白地図は手元に持ちます**（`priv/geo/japan_coast.json`。Natural Earth のパブリックドメインのデータを日本の範囲で切り、0.012 度で間引いたもの）。外の地図タイルを読みに行かないので、**手元だけで開けて、何を見ているかを誰にも知らせません**
- **操作は関連図と同じ**です（`assets/js/pan_zoom.js`。「関連図」の「図の操作」）。**開いたときは全体が見える倍率**から始まります
- **濃さは詰まり具合の順位**（広さあたりの件数の順）。区画は矩形を端から端まで覆うので海の上にも載ります —— 同じ濃さで塗ると全面が埋まり、島の形が沈みます。**値の比では塗れません** —— いちばん詰まった区画と外海の区画は 5 億倍離れていて、上位 1 割を基準にしても中央値が 0.14 まで落ちます
- **大きさは細くても本当のまま**です。見える太さまで太らせていた頃は 8,185 区画のうち 6,295 が下限に当たっていて、**寄っても本当の大きさに戻りませんでした**。足りないぶんは**画面 1px の縁**で補います（寄ると相対的に細くなるので、嘘が残りません）。**400 倍まで寄れて**、寄ると区画の境目が出ます —— いちばん細い区画は図の 0.009 なので、12 倍では 1px に届きません
- **角は端の座標を丸めて出します**（幅ではなく）。幅を別々に丸めると隣と端が合わず、**白い筋**になって出ます（実測で 6,127 区画）
- **並べ方はメルカトル。** 緯度をそのまま縦に使うと北へ行くほど横に潰れ、九州と北海道で形が変わって見えます
- **押しただけでは走りません。** 件数と「見終わったか」を読んでから頼めるよう、選ぶのと頼むのを分けてあります

**溜まったものは travel-log が読みます。** 1 店 1 文書で、タグ `食事処` で拾えます。

| travel-log の項目 | 収集の中身 | 誰が入れるか |
| --- | --- | --- |
| 名前 | 見出し | 辞典（同じ見出しは 1 件に畳まれる） |
| 座標 | `extra.lat` / `extra.lon` | 地図辞典が優先（食い違うものだけ AI が直す） |
| 地域 | タグ `地域:<都道府県>` / `extra.area` | 百科事典のカテゴリと地図辞典（無いものを AI が足す） |
| シリーズ / カテゴリ | タグ `ジャンル:…`（**先頭がシリーズ**） | 辞典のカテゴリ（抜けているものを AI が足す） |
| ランク | タグ `ランク:A〜E`（**地図の丸の大きさ**） | AI（`extra.pageviews_month` が目安） |
| 説明 | 本文の 2 行目以降 | 百科事典が優先、無ければ AI |
| 連絡先・公式サイト | `extra.phone` / `extra.website` | 地図辞典が優先 |
| （どの辞典から来たか） | タグ `出典:Wikipedia` / `出典:OSM` / `出典:Overture` | 機械（複数に居た店には複数付く） |

**閉店したものは墓標で消します**（Chiezo が消えた扱いにするタグ）。辞典は閉店をすぐには落とさないので、ここは AI にしか見分けられないところです。消す理由を本文に書かせているのは、消したものは名前が並ぶだけで、理由が無いと消し間違いに気づけないためです。

## 起動

`docker compose` で PostgreSQL ごと立てる。開発サーバーは `http://localhost:7000`。

```bash
cp .env.example .env   # SECRET_KEY_BASE と CHIEZO_BASE_URL を書く
docker compose up -d
```

`SECRET_KEY_BASE` は `mix phx.gen.secret` で作る。**64 バイト未満だと起動時に断る**
（通すと起動には成功して全リクエストが 500 になり、原因を追いにくい）。
移行は起動のたびに当たるので、手で流す必要はない。

手元のソースから作り直すときは重ねる。

```bash
docker compose -f docker-compose.yml -f docker-compose.build.yml up -d --build
```

ホストで直接動かすなら、DB だけ立てて繋ぐ。

```bash
docker compose -f docker-compose.dev.yml up -d
mix setup && mix phx.server
```

テストは DB が要る。外部への取得はスタブへ差し替えてあるので、ネットワークには出ない。

```bash
docker compose -f docker-compose.dev.yml up -d
mix test
```

**CSS を触ったら焼き直す。** 開発サーバーは watcher を持たない（`config/dev.exs` の `watchers: []`）ので、`assets/css/app.css` を変えても `priv/static` は古いままになる。直したのに画面が変わらないときはここを疑う。

```bash
mix tailwind tazuna   # JS も変えたなら mix assets.build
```

アイコンの原本は `priv/static/images/icon.svg`。変えたら PNG を作り直す。

```bash
docker run --rm -v "$PWD/priv/static:/w" -w /w debian:bookworm-slim sh -c \
  'apt-get update -qq && apt-get install -y -qq --no-install-recommends librsvg2-bin \
   && rsvg-convert -w 180 -h 180 images/icon.svg -o images/icon-180.png \
   && rsvg-convert -w 64 -h 64 images/icon.svg -o images/icon-64.png \
   && rsvg-convert -w 64 -h 64 images/icon.svg -o favicon.ico'
```

本番用イメージは `Dockerfile` でビルドする。イメージの中でスタイルと JavaScript も作る。公開時は `ghcr.io/<owner>/tazuna:<commit-sha>` のようにコミット SHA を含むタグを付ける。

基本設計は [docs/basic-design.md](docs/basic-design.md) を参照してください。
採用技術と選定理由は [docs/technology-selection.md](docs/technology-selection.md) を参照してください。
