# Chidori の全体像

README には概要だけを書いている。ここでは Chidori の立ち位置（Chiezo との関係・名前の由来・題材の線引き）、画面の構成、利用者が書いたことの置き場を書く。画面ごとの詳しい説明は [最新情報とトピック](news-and-topics.md)・[関連図](relations.md)・[データ収集](datasets.md) にある。

## 何をするアプリか

日々確認したいニュースや趣味の情報を、利用者ごとの関心に合わせて収集・要約し、適切なタイミングで知らせるアプリです。技術情報に限らず、暮らし、スポーツ、エンターテインメント、地域情報などを扱います。

Elixir と Phoenix で実装しています。トップページは置かず、`/` はニュースへ送ります。

## Chiezo との関係

Chidori は [Chiezo](https://github.com/rtcode337/chiezo) と利用者のあいだに立つ層です。Chiezo が知識と AI を持つ側で、Chidori がそれを人に見せ、人の意図を向こうへ渡します。

- Chiezo に溜まった情報を、読める形にして見せる（関連図・ニュース）
- 利用者の関心を Chiezo に伝える
- 何を集めてほしいかの指示を Chiezo に渡す（Chidori で読むものも、他のアプリで使うものも）

**名前は「知取（ちどり）」** —— 知を取って回る、千鳥のように各所を巡って拾う、を掛けています（Chiezo と並ぶ書き方で Chidori）。

**Chiezo で止めた収集も、画面から押した 1 回は走ります**（区画を指定して頼む・travel-log からの依頼・割り込み・「いま要約を作る」など）。AI の使い過ぎを気にして自動の回を止めていても、見て決めた 1 回は頼めるようにするためで、Chiezo に「人が押した 1 回」（`manual=true`）と申告して頼みます（`Chidori.Chiezo.by_hand/1`）。定時の時計（要約・情報収集）は申告しないので、止めた収集は時計では動きません。

**題材ごとの事情は Chidori が持ちます。** 「画家を集めてネットワーク図にする」のような文脈を Chiezo に持たせると、あちらが題材を選ぶ知識ベースになってしまいます。Chiezo は題材を選ばないまま置き、判断と見せ方はこちらに寄せる、という線引きです。

## 頭のメニューと設定

**トップページ（閲覧）は廃止しました**（`/` はニュースへ送る。`ChidoriWeb.PageController`）—— 読むものはニュース・イベント・趣味・ツールの画面に分けてあり、それを並べ直すだけのページを別に持つ理由が無くなったためです。技術書の未読の上位 10 冊と本棚は趣味の技術書のタブ、いま止めている通信はツールの画面にあります。

**頭のメニューは ニュース・趣味・イベント・ツール・収集・設定 です。** **イベント**（`/events`）は技術イベント・お笑いイベントの画面です（画面は最新情報のもので、`NewsLive` の `:events`。ニュースのタブには出さず、前の道 `/news?view=chidori_events` はイベントの道へ送る）。**ツール**（`/tools`）はその場の様子を見る道具の画面で、いまは Pi-hole のいま止めている通信を流します。趣味には、映画・アニメ（話題なので画面は最新情報のもの。道も `/news?view=chidori_movies` のまま —— 通知のリンクがこの形のため）、芸術家・芸能人（関連図。画面は関連図のもので、道は `/relations?view=…`）と、技術書の本棚・レシピ集・Pi-hole（`/datasets`）を 1 つのタブの段に並べます（並びは 映画・芸術家・技術書・レシピ・芸能人・アニメ・Pi-hole。`Chidori.Hobbies`）。**映画の関連図・映画館・見た映画は映画のタブの中**に置き、最新・関連図・映画館・見た映画を四角い札で切り替えます（`DiningTabs.movie_tabs/1`。見出しの下に置き、下に線を引いて区切る。見出しと説明は 4 つとも同じもの（`DiningTabs.movie_intro/1`）で、関連図の説明は切り替えの下に出す。機能ごとの見出しだと長さが違い、切り替えるたびに札の位置がずれた。映画館は `section=theaters`、見た映画は `section=seen` で、そのときはそれだけを出す）—— 映画を見に来た人が、最新の作品とつながりの図を行き来できるように。関連図はどれも趣味に並べたので、頭のメニューに「関連図」はありません（収集の画面の頭の段は 一覧・ニュース・趣味・イベント・他アプリ用）。映画・アニメはニュースのタブに出さず、開いているときは頭のメニューの「趣味」に印が付きます。

**画面は「読む画面」と「収集の画面」に分かれています。** 読む画面（ニュース・趣味・イベント・ツール）は集めたものと、利用者が書くもの（見た記録・お気に入り・興味トピック・読んだ記録）だけを出します。Chiezo へ頼む口 —— 収集の設定・巡回と相手・時刻・区画・1 回だけ頼む口・travel-log からの依頼・空き欄を埋める・名簿・書き出し・実行履歴 —— は頭のメニューの「**収集**」（`/collect`）にまとめ、話題・図・データごとの収集の画面（`/collect/news?view=…`・`/collect/relations?view=…`・`/collect/datasets?view=…`・`/collect/apps?view=…`）から頼みます。読む画面と収集の画面は互いにリンクで行き来できます。例外は見ている 1 件から頼む口（記事・本・人の詳細の「頼む」と、映画のタブの中の「見た映画」の「見た映画を足す」）で、読む画面に残しています（見ている 1 件から頼む流れを崩さないため。結果は収集の画面の履歴で見ます）。ご当地グルメ・アニメ聖地・食事処は Chidori では読まない（読むのは travel-log）ので、収集の画面の「他アプリ用」にだけあります（「データ収集」には Chidori で読む対象だけを並べる）。

**収集（`/collect`）** は Chidori が Chiezo に頼んでいる収集の一覧です（巡回ごとの間隔・相手・前回・次回・走らない理由）。ワーカーの起きる間隔と 1 回に流す数、待っている回、取り込みの待ち行列も並べます（Chiezo の `GET /v1/collect/queue`）。**待ち行列が溜まってきたときに、何がどれだけの間隔で回っているかを 1 枚で読むため**のものです。収集は **Chidori の画面の並び**（最新情報の話題とそのトピック → 関連図 → データ収集と本棚）で、Chiezo にまだ送っていないものも並びます。**収集ごとに、巡回の相手と整理を自動で回すかを選んで「Chiezo に送る」で送れます** —— 送るのは各画面の「収集の設定を更新」と同じもので、Chidori の今の依頼文も一緒に届きます（`Chidori.CollectCatalog`）。**Chiezo の今の設定が Chidori の定義と違う収集には「Chidori の定義と違います」を出し、違う項目（依頼文・絵の拾い方・足りない巡回など）を並べます**（`Chidori.CollectDrift`）—— 直した依頼文が「収集の設定を更新」を押すまで届かないことに気づけるように。頼む相手と、止めた・動かしたは比べません。**止まっている収集は塊ごと色を付け**（各収集の画面の設定の枠も同じ色。この収集から作る収集は節ごと）、**収集ごとの「止める」「動かす」で切り替えられます**（Chiezo の `POST /v1/collect/{name}/enabled`。`Chidori.Chiezo.switch/3`）。止めるのはいつでもできますが、**動かすのは Chiezo の管理画面の収集の面で「外部からの有効化を許可する」を押したときだけ**です（許可していなければ、そう出ます）—— 動かすと AI が回り始めるので、許可するかどうかは Chiezo の側で決めます。Chidori の画面に無い収集（Chiezo にだけ残っているもの）は後ろに並び、相手と整理だけを送ります（Chiezo の `PATCH /v1/collect/{name}/sweeps/{sweep}`）。**各収集の画面の設定の枠にも「止める」「動かす」を置いています**（設定の見出しの行の右端。この収集から作る収集を持つ対象は節の見出しの行。設定の枠は開け閉めしません。収集の一覧と同じ。Chiezo で外部からの有効化を許可していなければ、「動かす」の代わりに Chiezo の管理画面のその収集の面への入口を出す。`ChidoriWeb.CollectSwitch`・Chiezo の `GET /v1/collect/{name}` の `outside_switch_allowed`）。**各収集の画面の巡回の表には、巡回ごとに「今すぐ走らせる」を置いています**（人が押した 1 回として頼むので、止めた収集でも走る。ふつうの回なので進み具合も次の予定も進む。時計を持たない割り込み用の回と手で回す回には出さない。`ChidoriWeb.RunSweepButton`）。**Chiezo の管理画面のボタンと同じ操作も、収集ごとの「ほかの操作」から頼めます** —— 最後の 1 回をやり直す・巡回ごとの一周をやり直す・区画を割り直す・全部を未確認に戻す・走っている取り込みを止める・検索文の控えを見る / 消す（Chiezo の `POST /v1/collect/{name}/redo` ほか。`Chidori.Chiezo.operate/3`）。ワーカーの表からは止める・動かす・今すぐ起こすを頼めます（`POST /v1/ai/workers/{id}/paused`・`…/wake`）。Chiezo の管理画面を開くのは、外部からの有効化の許可・名前の変更・データごとの削除・世代を戻す・ワーカーの作成と変更・AI の相手と鍵のときだけです（取り消せない操作と、ほかのアプリとも共有する設定）

**設定ページ（`/settings`）** は 2 つのタブに分かれています。

- **写真と表紙** —— 顔写真・レシピの写真・技術書の表紙を取る様子です。Chidori の頼みの列（待っている数・休んでいれば明ける時刻・直近の結果）と持っている写しの数、Chiezo が外の絵を取れているか（最後に取れた時刻・続けて取れなかった回数と理由・断られて休んでいる相手）と直近の依頼（Chiezo の `GET /v1/thumbs/health`）を並べます。**頼みが Chidori の列で待っているのか、休んでいるのか、Chiezo へ届いて断られているのかを 1 か所で読むため**のものです（開いたときに読むだけで、自動では読み直しません）
- **通知** —— 要約ができたときの知らせ先。ntfy の宛先と、通知を受け取るように登録した端末（[まとめを ntfy で知らせます](news-and-topics.md#まとめを-ntfy-で知らせます)・[端末へ通知します（PWA）](news-and-topics.md#端末へ通知しますpwa)）

## 利用者が書いたことの置き場

**興味トピックと、読んだ・見た記録（技術書・関連図・Pi-hole のドメイン・映画とアニメ）とニュースのお気に入り・お気に入りの映画館は、Chidori の DB ではなく Chiezo の名前付きの置き場 `chidori_data` に預けます**（`Chidori.DataStore`）。動かす場所を変えたり DB を作り直したりしても消えず、同じ Chiezo を見ている Chidori どうしで共有できます。置き場は無ければ起動時に作ります。起動時に全部を読んで手元に持ちます。画面を開いたときに置き場の件数と最後に書かれた時刻を Chiezo に聞き、読んだときと違えば全部を読み直します（ほかの Chidori が書いた記録も、開き直せば出ます。Chiezo が 3 秒で答えなければ前の写しのまま開きます）。1 件 1 文書で、タグ `興味トピック` / `見た・読んだ` で分け、中身は脇書き（extra）に持ちます。

起動時に全部を読んで手元に持ち、書くときは Chiezo に書いてから手元を直します。Chiezo に届かない間は空として扱い、書くのは断ります（30 秒おきに読み直す）。
それ以外の設定（トップの並び・通知・控えている依頼など）は、その Chidori ごとのものなので DB に持ちます。巡回の間隔・整理を止める収集・知名度の下限は、収集の画面（`/collect`）の「Chiezo から戻す」で、食事処の範囲は範囲の画面で、Chiezo の収集から戻せます。
